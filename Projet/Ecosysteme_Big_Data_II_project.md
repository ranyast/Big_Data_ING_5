# Big Data project

## Objective

Design and implement an end-to-end data processing pipeline, from raw data storage to analytical processing, using the technologies covered in the Onyxia course.

## Deadline

Friday 4 december 2026

## Instructions

### 1. Project selection

You are free to choose the domain, dataset, and research question, subject to the following conditions:

- The dataset must be different from those covered in the various modules.
- The total size of the raw data must be between **1 Mo and 5 Mo**.
- The data must be public, synthetic, or generated by the team, and its source must be documented.
- A specific issue that yields verifiable results.
- Data that can be processed using the resources available on Onyxia.

You have complete freedom in choosing the research question, processing steps, and tools. You must justify your approach and prove that you actually executed it on the cluster.

### 2. Required tasks

The project must include:

1. Storage of raw data on Onyxia’s S3 object storage.
2. The pipeline must produce at least one final dataset that addresses your research question.
3. Proof of execution and independent verification of at least one result.

### 3. Required deliverables

The final project must be submitted to a Git repository. The repository must be public and contain at least 10 commits, spread over several days, with visible contributions from both team members. It must have the following directory structure:

```text
bigdata_project
├── README.md
├── evidence/              # numbered screenshots 01_..., 02_..., etc.
├── src/                   # all code (SQL, Python, YAML, Hop workflows...)
└── k8s/                   # Kubernetes manifests used, if applicable
```

README.md: It must fit on one page and contain the following, in this order:
- Authors: last names, first names.
- Prerequisites.
- Dataset: name, URL, license, download date, size.
- Problem statement in 3 sentences or fewer.
- S3 paths (bucket and prefixes) for raw and processed data.
- Procedure for reproduction: provide step-by-step execution commands, restart methods, and any other necessary details.

The needed files to reproduce the project must be provided. Any data or dependencies not included must be accessible via a clearly documented procedure.

Report: 4 pages maximum
- Format: PDF.
- Sent by email.
- Add the link to the Git repository of the project.
- Problem statement, justification and description of the dataset, source, size, and schema.
- Diagram of the processing workflow and justification for technical choices. Alternatives considered and reasons for their rejection, supported by your own measurements.
- Data quality issues encountered in your data (real examples, number of affected rows) and the processing applied.
- Results obtained and limitations.
- How the results would change if the dataset were 100 times larger.
- Evidence: This must be referenced in your report. Each screenshot must clearly show your Onyxia ID or namespace, as well as the date and time. At a minimum, you must include:
  - the contents of your S3 bucket (raw and processed data)
  - an execution trace for each component used

## How to send a project for evaluation?

Send an email containing the following:
- Subject format: "Ecosystème Big Data II - <Group number (ex: Gr02)> - <LASTNAME1 Firstname1> - <LASTNAME2 Firstname2>"
- Report: in PDF format, maximum 4 pages, including appendices.

## Additional information

- Every initiative will be counted, just don't forget to describe it in your report.
- Late submission: -1 point per day of delay.
- If the entire raw dataset exceeds size limits, a penalty of −1 point will be applied.
- Reports exceeding 4 pages, including appendices: any pages beyond this limit will not be read.
- Evidence without a visible identifier or date: will not be counted.
